# SyNG-BTS-TCGA-Supplement

Reproducibility materials for the SyNG-BTS TCGA study, including cohort definitions,
preprocessing and benchmark workflows, downstream analyses, and figure source data.


## What this repository is

The full reproducibility record of how the SyNG-BTS was used for the manuscript: which TCGA cohorts, which preprocessing, which generative configurations, and which downstream benchmarks produced each published figure and table.
Important: It is not the software and not meant for use/adoption by users. `syng-bts` is a separate package, pinned here as a dependency.


## Python and R environments

Both environments are locked, which is very important for reproducibility. The lockfiles make "same code" also mean "same environment", so a rerun reproduces the published values rather than merely similar ones if any of the dependencies have changed.

There are environments, because the workflow is split between R and Python. Setup is two commands:

```bash
uv sync                       # Python
Rscript -e 'renv::restore()'  # R
```

So far the lockfiles are only starting points, not the finished environments. Python currently holds `syng-bts` plus `h5py`, `pandas`, `numpy`, `matplotlib`, and `scipy`. R holds `DANA`, its four imports, and its suggested Bioconductor packages: `edgeR`, `DESeq2`, `limma`, `sva`, `RUVSeq`, `EDASeq`, `Biobase`, and `ggnewscale`. Please add dependencies and packages for each stage as needed, and re-lock both environments, as described below.


### Python with uv

Use [uv](https://docs.astral.sh/uv/) rather than pip or conda, because it resolves the whole dependency set into a lockfile, so a rerun at any point installs the same versions instead of whatever is current on PyPI.

Two files are the basis:
- **`pyproject.toml`** is written by hand and says what we depend on. `syng-bts` is pinned exactly with `==`, not `>=`. 
- **`uv.lock`** is generated by `uv` and lists every dependency at an exact version. Never edit it by hand. Always commit it.

```bash
uv lock                              # resolve pyproject.toml into uv.lock
uv sync                              # build local python environment .venv to match the dependendies in uv.lock exactly
uv add matplotlib                    # add a dependency to the project. This also updates both files together
uv run workflow/04_generate/run.py   # run a workflow using the locked environment
```

Use `uv run`, never a bare `python`. A bare `python` takes whatever interpreter is on your PATH, which defeats the point of locking.


### R with renv

Same idea as `uv` for R: `renv.lock` pins every package version, and the library lives in the project instead of your user library. `.Rprofile` activates it, so any R session started in this directory already uses the project library.

```bash
Rscript -e 'renv::restore()'       # install exactly what renv.lock specifies
Rscript -e 'renv::install("pkg")'  # add a (new) package to the project library
Rscript -e 'renv::snapshot()'      # record current library versions into renv.lock
Rscript -e 'renv::status()'        # compare current library against the lockfile
```

Commit `renv.lock`, `.Rprofile`, and `renv/activate.R`. **Never** commit `renv/library/` (installed packages, hundreds of MB, platform-specific) or `renv/staging/` (temporary files).

Installing additional packages from GitHub and Bioconductor into the project library is slightly different, see below:

```bash
Rscript -e 'renv::install("github::LXQin/DANA")'   # GitHub package
Rscript -e 'renv::install("bioc::DESeq2")'         # Bioconductor package
```

## Layout

| Path | What belongs there |
|---|---|
| `config/` | Group-label definitions, preprocessing specification, per-cohort filtering cutoffs, generation parameters. Added alongside the stage that reads them. |
| `workflow/` | One directory per stage, each with a single entry point `run.R` or `run.py`. See `workflow/README.md` for details. |
| `src/python/`, `src/R/` | Helpers used by **more than one** stage. Single-stage helpers stay in the stage directory. |
| `data/` | Local workspace. Contents are gitignored. Downloads and preprocessing results go here, but should not be committed. |
| `results/` | Small tidy CSVs, including the source data behind every manuscript figure and table. Committed. |
| `figures/` | Final manuscript figures, built by workflow stage 07. Committed. |



## Configuration

Everything that defines the published analysis should live in `config/`, ideally not hard-coded in script bodies. A parameter buried in a script is invisible to a reader checking what was actually run.

Add each file together with the stage that reads it. Currently present: `tcga_cohorts.tsv` and `tcga_download.yml` (stage 01). Further examples:

| File | Holds |
|---|---|
| `tcga_cohorts.tsv`, `tcga_download.yml` | TCGA query, source version, and the cohort list. Read by stage 01. |
| `datasets.tsv`, `group_maps.tsv` | Per dataset: the clinical variable, Biotab column, recode rule, and published sample/marker counts. Read by stages 02 and 03. |
| `preprocess.tsv` | Marker-filtering paths and the auto-threshold binning parameters. Read by stage 03. |
| generation | Models, hyperparameters, generated sample counts, etc. |

Formats: Ideally use **TSV** when there is one row per cohort, something like **YAML** for nested or optional parameters.


## Suggestions for adding workflow stages

1. **One entry point per stage.** `workflow/*/run.R` or `run.py`, taking no required arguments. Everything else in that directory is its own helper code.
2. **`src/` is for shared code only.** Code used by exactly one stage stays in that stage's directory.
3. **Cohort lists and per-cohort settings come from `config/`.** Never hardcode a cohort name or a filtering cutoff in a script.
4. **Write only into `data/`, `results/`, or `figures/`.**


### Seeds

Seeds are hardcoded. We can simply use a named constant in each script as an exact record.

- Ideally one `SEED` constant at the top of each entry point. No scattered `set.seed()` calls.
- The seed should be explicitly passed to every stochastic call.
- If necessary, per-cohort seeds derived in code from that constant.
